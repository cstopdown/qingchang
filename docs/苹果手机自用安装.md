# 苹果手机自用安装

轻唱的 iOS 版本面向自己的 iPhone。共享界面与音频业务通过 Capacitor 放进 WKWebView，不需要为个人使用建设社区或提交 App Store。本轮已增加环境检查、模拟器构建与设备运行入口，以及统一录音中断处理。

当前机器只有 Command Line Tools，没有完整 Xcode、iPhone SDK、`simctl` 或 `devicectl`。工程同步和静态检查已完成，尚未编译出 iOS 应用、生成 IPA、签名或在 iPhone 运行。既有 Mac、Windows 与 Android 安装包属于上一版，不包含本轮改动。

## 准备条件

轻唱要求 iOS 16.4 或更新系统。截至 2026-10-30，[Capacitor 官方 iOS 文档](https://capacitorjs.com/docs/ios)自身支持 iOS 15+，要求 Xcode 26.0+；轻唱根据共享 Web 代码的实际运行要求，将 Web 构建目标与原生应用最低部署版本设为 16.4。当前 SPM 依赖包由 Capacitor 同步生成 `.v16`，它是依赖兼容下限，不改变应用 16.4 的可安装下限。

需要一台兼容该 Xcode 的 Mac、自己的 iPhone，以及用于在 Xcode 登录的 Apple 账号。[Apple 官方账号说明](https://developer.apple.com/help/account/basics/about-your-developer-account)支持使用免费 Personal Team 将应用安装到个人设备。免费配置文件自签发起 7 天过期，到期后需要重新构建并安装。Apple 同时限制免费 Team 的 App ID、设备和每台设备安装数量，实际额度以该官方页面与 Xcode 提示为准。

## 工具命令与输出

在项目目录先运行 `npm ci`，再按目的选择命令：

| 命令 | 行为与边界 |
| --- | --- |
| `npm run ios:check` | 读取真实 `xcodebuild` 版本，要求 26+，并检查 `iphoneos` 与 `iphonesimulator` SDK；不编译应用 |
| `npm run ios:sync` | 构建共享 Web 资源并同步 Capacitor 插件与 iOS 工程；同步成功不代表原生编译成功 |
| `npm run ios:build` | 先检查环境，再同步并使用共享 `App` scheme 构建 Debug 通用 iOS 模拟器应用，关闭代码签名；输出不是 IPA，也不能直接装到真 iPhone |
| `npm run ios:run -- --list` | 检查环境后列出 Capacitor 可运行目标，不执行资源同步 |
| `npm run ios:run` | 检查环境、同步资源，再通过 Capacitor 选择设备或模拟器运行；真机需要自己的签名配置 |
| `npm run ios:open` | 在 Xcode 打开工程，不代表已编译或安装 |

模拟器构建默认输出为 `ios/DerivedData/simulator/Build/Products/Debug-iphonesimulator/App.app`，该目录不纳入 Git。本机因缺少完整 Xcode，尚未生成这个文件。`ios:run` 还可传 `--target <UDID>` 或 `--configuration Release` 等 Capacitor 参数；设备 ID 来自实际目标列表，不预设虚构设备或 Team。

当前机器运行 `ios:check`、`ios:build` 和 `ios:run -- --list` 都以 exit 1 停止，明确提示“需要完整 Xcode 26+；Command Line Tools 不包含 iOS SDK”。需要先安装并完成完整 Xcode 的首次启动；如要临时选择指定安装，可通过 `DEVELOPER_DIR` 指向它的 `Contents/Developer`，无需把环境检查失败当作编译通过。

## 自用签名与安装

1. 在 Mac 安装并打开完整 Xcode，完成它提示的必要组件准备；在 Xcode 的账号设置中登录自己的 Apple 账号。账号只需要在自己的 Xcode 中使用。
2. 运行 `npm run ios:check`；检查通过后执行：

   ```sh
   npm run ios:sync
   npm run ios:open
   ```

3. 在 Xcode 的 `App` Target 选择 Signing & Capabilities，启用自动签名，并选择自己的 Personal Team。项目不预填 Team；若应用标识与现有标识冲突，设置为自己唯一的 Bundle Identifier。
4. 连接并解锁自己的 iPhone，按设备与 Xcode 提示完成信任与开发者模式准备，选择该设备并点击运行；也可完成签名配置后使用 `npm run ios:run`。
5. 首次录音允许麦克风访问。戴有线耳机，先测试麦克风和耳机返听，再录制短片段，核对音量、音色、延迟与作品导出。

工程已包含共享 scheme、麦克风用途说明和隐私清单。隐私清单声明 Filesystem 的文件时间戳访问用途并加入应用资源；这些是工程配置，不能代替设备权限或发布验证。

## 锁屏、后台与录音中断

录音应在前台进行。源码统一处理页面隐藏、原生应用进入后台、正在使用的音频上下文停止运行，以及输入轨道结束或静音等中断信号：停止麦克风、当前返听与伴奏，保存已经收到的声音片段。尚无可用声音时不生成空作品；保存失败时保留待保存内容，可重试保存。

回到前台或音频上下文恢复后，应用不会自动打开麦克风或继续录音。请先确认已保存的片段，再手动开始下一次录音。Chrome 已验证受控中断与保存恢复，iPhone 的锁屏、来电和系统挂起时序仍需真机验收。

## 工程检查与后续维护

本轮已完成资源同步、Info / Privacy / 工程 plist 检查、共享 scheme XML 与脚本语法检查。CI 已配置 iOS 模拟器构建和压缩包上传，但尚未运行远端 CI，也不能据此宣称原生编译通过。具体结果见[验收记录](./验收记录.md)。

修改共享界面、音频代码或演示素材后，重新同步并构建或运行。免费 Personal Team 的 7 天配置文件到期后，需要重新构建安装。曲库与作品保存在当前应用环境中，重要作品请导出留存。

## iPhone 界面适配

本轮源码加入顶部、底部及左右安全区留白，表单输入采用 16px 字号，关键触控按钮至少 44px，并让缩小可视高度后的导入表单可以内部滚动提交。桌面 Playwright WebKit 的持久配置已验证音频与歌词导入、收藏和刷新保留，以及手机纵横屏和 iPad 尺寸下的布局。

验收截图文件名带有 `iOS-WebKit`，实际是桌面 WebKit 模拟视口；安全区数值为显式 CSS 变量模拟，不是从真 iPhone 测得。系统键盘、真实安全区、权限和音频路由仍需设备验收。

## 真机验收

完成 Xcode 编译和个人签名安装后，应在自己的 iPhone 验证完整伴奏录音与导出，并核对锁屏、切后台或输入中断后的已有片段保存、返听停止和回到前台后的停止状态。再检查安全区内控件、文件选择、系统分享、重启后的曲库保留，以及连接个人 Mac 的 AI 服务。浏览器模拟视口或静态工程检查不能代替这些设备验收。
