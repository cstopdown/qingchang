# 产品与架构

## 首期目标

轻唱首先完成个人离线练唱闭环：选一首伴奏、读同步歌词、录下人声、在本机混合，再试听和导出作品。界面与业务共用 React、TypeScript 和 Web Audio；Electron 承载 macOS / Windows 桌面，Capacitor 承载 Android / iOS。iOS 首先仅供自己的 iPhone 使用，当前不建设社区或云端服务。

“本地模式”表示曲库与作品不依赖云端服务。第三方站点入口及远程音频直链导入仍然需要联网。网页版本首次加载也需要访问部署站点；本期没有实现 PWA 资源离线缓存。桌面、Android 和 iOS 将静态资源随应用打包。

## 音频链路

伴奏解码为 `AudioBuffer` 后进入 Web Audio 播放。录音由用户手势启动并请求麦克风，音频工作线程收集人声 PCM；界面展示麦克风电平和实时音高参考。伴奏、人声音量、混响与延迟补偿用于生成本地混合作品，作品保存为 WAV Blob。耳机返听单独控制，避免默认把麦克风直接播放到扬声器。

实时音高只估计当前输入声音的频率、音名和偏差。应用没有曲谱、标准旋律或逐音符对齐，因此不生成歌曲音准分数。原唱导入会保留其中的人声，本期不执行人声分离。

## 数据与初始化

IndexedDB 数据库为 `qingchang-library`，包含 `tracks`、`recordings` 与 `meta` 三个对象仓库。歌曲和录音包含真实 Blob，不把音频编码成长字符串写入本地存储。

首次启动会读取随包提供的三首演示 WAV，再用同一个读写事务检查初始化标记并写入曲目。初始化中的并发调用共享同一个 Promise；多个窗口也以事务中的标记为准，避免重复覆盖。资源读取或写入失败会向界面抛出错误，初始化 Promise 可重试；没有成功写入时不会伪造已完成标记。删除演示曲不会删除初始化标记，因此刷新不会恢复它。

本地文件导入在外部文件边界检查格式候选与 100 MB 大小限制，再由 `decodeAudioData` 真正解码并取得时长，成功后才保存。HTTP(S) 直链使用浏览器标准 CORS `fetch`，不携带跨站凭证；流式读取过程中限制 100 MB，音频解码成功后才入库。HTTP 成功状态不能证明内容是音频，HTML 页面同样会在解码时被拒绝。

歌曲 `origin` 记录演示、本地或直链来源，不判断是否存在原唱。删除歌曲保留已经录制的独立作品。收藏保存在歌曲记录中，录音设置由音频模块维护。

## 平台边界

桌面只在受信任本地内容中暴露受限的文件保存和打开外链能力，远程站点进入外部浏览器。Android 与 iOS 使用 Capacitor 的文件系统、浏览器与分享接口。各平台对麦克风、音频解码、文件导出和应用签名的支持必须以实测为准，见[验收记录](./验收记录.md)。

## 后续路线，尚未实现

| 方向 | 实施前需要明确的问题 |
| --- | --- |
| 账号与社区 | 账号身份、隐私设置、内容治理及服务端成本 |
| 作品云端发布 | 用户授权、对象存储、访问权限、删除与分享生命周期 |
| 合唱 | 音频时间对齐、分轨传输、延迟策略及多人授权 |
| 歌曲音准评分 | 有权使用的标准旋律、歌声对齐、设备误差与评分解释 |
| 人声分离 | 模型质量与授权、端侧算力、推理时延及原唱残留 |
| 曲源 API 接入 | 第一方文档、授权、稳定协议与明确的使用限制 |

这些方向不包含在当前功能闭环中，也未以空接口或模拟数据代替实现。
