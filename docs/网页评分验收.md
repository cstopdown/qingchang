## 生产浏览器闭环

在独立 Chrome 156 配置中访问实际生产入口 `http://127.0.0.1:8765/`，未把 Vite 开发页面作为生产验收。受控麦克风输入用于验证音频链路，不能替代真人麦克风、蓝牙和耳机主观听感。

- 麦克风预览、返听与音色、导入、录制、跨页结束、作品保存、回放、WAV导出及刷新持久化通过。
- 自制音阶 WAV 输入时，CREPE约10.3秒就绪；录制中实际显示音高与参考指标。录制4.908秒后，IndexedDB作品保留 `realtimeScore`、固定模型ID和 `qingchang-c-major-v1` 参考身份。输入未与参考时间同步，因此本次指标不代表真人唱功。
- 导入偏移3秒的音高JSON后，再绑定参考人声，偏移仍为3秒。异步参考提取完成时不能将原曲目的参考绑定到另一首当前曲目或正在录制的会话。
- 真实VocalSet干声经页面提交到VocalVerse，返回v2报告，`inputKind=dry-vocal`、`modelCalled=true`、`scorable=true`；页面展示原分，刷新后报告ID和内容保留。该真实浏览器测试1项通过，非跳过。
- 1440桌面与390手机宽度下录音界面无横向溢出，参考面板和评分内容可读。数字及文件选择控件保持浏览器原生样式。

最终 `8d23922` 发布后再次执行真实评分浏览器测试，1项通过，约19.4秒，报告显示最新实验限制。截图已由主 Agent 复核：[桌面实验分数](../artifacts/网页评分-桌面实验分数.png)、[手机实验分数](../artifacts/网页评分-手机实验分数.png)、[参考面板](../artifacts/网页评分-参考面板.png)。本轮有一次私有健康检测超时，随后真实健康响应为ready且评分重试成功；该次超时的具体原因未确定。

首次CREPE加载期间极短录音可能先结束，分析超时会明确显示，原始录音仍保存。离线参考提取有独立时限，不受录制结束3秒分析时限约束。

## 已知质量限制

同一清唱的原音、中度退化、重度退化分别输出 **66.80、70.24、82.10**，加噪与失真反而提高了分数。3秒合成器乐也得到79.62。当前模型未通过这组录音质量单调性检验，既不能用作唱功或录音质量判断，也不能当作人声分类器。

界面和API均明确标注模型实验分数；保留原始值，不反转、不伪造校准，不生成四维点评。详细派生处理、原始响应、哈希、许可和限制见 [CPU 服务实测](../vocal_service/部署与验收.md)。实时参考音准、节奏与覆盖率和该实验分数分别呈现。

## 公网入口

`http://106.14.75.30:9000/` 为HTTP静态预览，`isSecureContext=false`，不能使用麦克风，`/ai/health`返回404。自制音阶曾在真实公网页面成功进入工作室；UUID已统一使用非安全上下文可用的 `crypto.getRandomValues`。

早期验收发生过CSS和JavaScript资源连接拒绝，不能把这些轮次算作公网完整导入或视觉通过。后续只读诊断中，服务端与Mac公网CSS各3次均200；服务端无OOM、重启或监听队列溢出，尚无证据确定之前连接失败的根因。最终版真实Chrome的样式加载与本地WAV导入均成功，见 [公网导入截图](../artifacts/网页评分-公网导入.png)。一次通过不证明网络长期稳定；完整录音与评分验证使用SSH本机入口，HTTPS域名仍待申请。
